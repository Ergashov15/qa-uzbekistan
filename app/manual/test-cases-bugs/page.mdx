# 📝 Test Case va Bug Report yozish

Har qanday QA mutaxassisining kundalik faoliyati **Test Case** va **Bug Report**lar yozishdan iborat.

---

## 1. Test Case tuzilishi

**Test Case** — ma'lum bir funksiyaning to'g'ri ishlashini tekshirish uchun zarur bo'lgan shartlar, qadamlar va kutilgan natijalar to'plamidir.

### Test Case asosiy maydonlari:
1. **ID:** Unikal identifikator (masalan: `TC-AUTH-001`).
2. **Title (Sarlavha):** Nimani tekshirayotganingiz haqida qisqa va aniq ifoda.
3. **Preconditions (Old shartlar):** Testni boshlashdan oldin bajarilishi lozim bo'lgan holat (masalan: *Foydalanuvchi tizimdan chiqqan bo'lishi kerak*).
4. **Steps (Qadamlar):** 1, 2, 3 tartibida aniq bajariladigan harakatlar.
5. **Test Data:** Kiritiladigan ma'lumotlar (masalan: `test@example.com`, `Parol123!`).
6. **Expected Result (Kutilgan natija):** Dastur qanday javob qaytarishi kerak.
7. **Actual Result (Haqiqiy natija):** Test vaqtida amalda nima sodir bo'ldi.
8. **Status:** `Pass` (o'tdi), `Fail` (xato), `Blocked` (to'silgan).

---

## 2. Bug Report (Nuqson haqida hisobot)

**Bug Report** dasturchi muammoni tez va oson tushunishi hamda o'z kompyuterida qaytara olishi (reproduce) uchun to'liq ma'lumot berishi kerak.

### Bug Report andozasi:
* **Title:** Qayerda, qachon va qanday xato ro'y berdi?
  * *Yomon sarlavha:* "Tugma ishlamayapti"
  * *Yaxshi sarlavha:* "[Login] Parolni tiklash tugmasi bosilganda 500 Server Error xatosi chiqmoqda"
* **Severity (Jiddiylik):** Xatoning tizimga ta'siri darajasi (`Blocker`, `Critical`, `Major`, `Minor`).
* **Priority (Muhimlik):** Xatoni tuzatish tezligi (`P1 - Immediate`, `P2 - High`, `P3 - Medium`, `P4 - Low`).
* **Environment (Muhit):**
  * OS: Windows 11 / macOS Sonoma
  * Browser: Chrome v128 / Safari v17
  * Server: Staging / Production
* **Steps to Reproduce (Qaytarish qadamlari):**
  1. `https://example.com/login` sahifasini oching.
  2. "Parolni unutdingizmi?" tugmasini bosing.
  3. Ro'yxatdan o'tgan email manzilini kiriting.
  4. "Yuborish" tugmasini bosing.
* **Expected Result:** "Emailga tasdiqlash xati yuborildi" xabari ko'rinishi lozim.
* **Actual Result:** Sahifada "500 Internal Server Error" paydo bo'ldi.
* **Attachments:** Ekran tasvirlari (screenshot), video yozuvlar yoki konsol/tarmoq loglari.

<Callout type="info">
  **Oltin qoida:** Dasturchiga shunday hisobot beringki, u sizdan qo'shimcha savol so'ramasdan xatoni topa olsin.
</Callout>
