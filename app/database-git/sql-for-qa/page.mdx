# QA Muhandisi uchun SQL va Ma'lumotlar bazasi

Zamonaviy QA mutaxassisi faqat brauzer interfeysini ko'rish bilan cheklanmasdan, foydalanuvchi yuborgan ma'lumotlar bazada to'g'ri saqlanayotganini tekshira olishi shart.

---

## 1. Nima uchun QA ga SQL kerak?

* **Back-end va Baza yaxlitligi:** Saytda "Ro'yxatdan o'tdingiz" deb chiqdi, lekin ma'lumotlar bazasiga foydalanuvchining paroli ochiq matnda (hashlanmasdan) yozilib qolgan bo'lishi mumkin.
* **Test ma'lumotlarini tayyorlash:** Kerakli holatdagi foydalanuvchilarni (masalan, balansi 50 000 so'm bo'lgan yoki statusi bloklangan) to'g'ridan-to'g'ri baza orqali tayyorlash.
* **Hisobotlar va statistika to'g'riligi:** Admin paneldagi diagrammalar va jami summalar bazadagi real raqamlar bilan mosligini tekshirish.

---

## 2. Eng ko'p ishlatiladigan SQL so'rovlar

### Ma'lumotlarni saralab olish:
```sql
-- Muayyan shart bo'yicha faol foydalanuvchilarni topish
SELECT id, email, created_at, status 
FROM users 
WHERE status = 'ACTIVE' 
ORDER BY created_at DESC 
LIMIT 10;
```

### Jadvallarni birlashtirish (JOIN):
Foydalanuvchi va uning buyurtmalarini tekshirish:
```sql
SELECT u.email, o.id AS order_id, o.amount, o.status
FROM users u
INNER JOIN orders o ON u.id = o.user_id
WHERE o.status = 'PENDING';
```

### Guruhlangan ma'lumotlar va agregat funksiyalar:
```sql
-- Har bir foydalanuvchi jami qancha buyurtma qilganini hisoblash
SELECT user_id, COUNT(*) AS total_orders, SUM(amount) AS total_spent
FROM orders
GROUP BY user_id
HAVING SUM(amount) > 1000000;
```

---

## 3. Baza sinovida nimalar tekshiriladi?

1. **Ma'lumotlar turlari va uzunligi (Data types):** Masalan, telefon raqami ustuni harflarni qabul qilib yubormayaptimi?
2. **Noyoblik (Uniqueness):** Bitta email bilan ikkita hisob ochilib qolmasligi (`UNIQUE` constraint).
3. **Null qiymatlar:** Majburiy maydonlar bo'sh (`NULL`) qolmasligi.
4. **Xavfsizlik (SQL Injection):** Qidiruv maydoniga `' OR '1'='1` kiritilganda butun baza ma'lumotlari sizib chiqmasligi.

<Callout type="info">
  **Maslahat:** Production bazasida hech qachon `UPDATE` yoki `DELETE` so'rovlarini `WHERE` shartisiz yurgizmang! Sinovlar uchun har doim test (staging) bazasidan foydalaning.
</Callout>
