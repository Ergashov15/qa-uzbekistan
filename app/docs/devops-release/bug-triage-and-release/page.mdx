# Bug Triage va Reliz Boshqaruvi

Har qanday dasturiy loyihada xatoliklar doimo topiladi. Muhimi — ularni qanday saralash va relizga chiqishga ruxsat berish yoki bermaslik bo'yicha to'g'ri qaror qabul qila olishdir.

---

## 1. Bug Triage Uchrashuvi (Bug Triage Meeting)

**Triage** — bu shifoxonalarda og'ir bemorlarni saralash kabi, yangi ochilgan barcha xatoliklarni ko'rib chiqib, ularning taqdirini hal qilish yig'ilishidir.

### Uchrashuv qatnashchilari:
1. **QA Lead / QA Engineer:** Xatoning texnik tafsilotlarini, takrorlash qadamlari va jiddiyligini (Severity) tushuntiradi.
2. **Product Owner (PO):** Xatoning biznesga va mijozlarga ta'sirini baholaydi va uning muhimligini (Priority) belgilaydi.
3. **Engineering Lead (Dasturchilar yetakchisi):** Xatoni tuzatish qancha vaqt olishi va uning atrofidagi xatarlarni aytadi.

### Har bir xato bo'yicha qabul qilinadigan 4 ta qaror:
* **Hozir tuzatilsin (Fix Now):** Relizni to'xtatib turib, zudlik bilan tuzatish kerak bo'lgan kritik xato.
* **Keyingi sprintga qoldirilsin (Defer):** Muhim, lekin relizni to'xtatishga arzimaydi.
* **Tuzatilmasin (Won't Fix):** Xato dasturiy ta'minot talablariga mos yoki foydalanuvchilarga hech qanday ta'siri yo'q.
* **Qo'shimcha ma'lumot kerak (Need Info):** Qadamlar noaniq bo'lsa, xato muallifiga qaytariladi.

---

## 2. Go / No-Go Qarori (Relizga ruxsat berish)

Dasturni yangi versiyasini foydalanuvchilarga chiqarishdan oldin jamoa **Go / No-Go** yig'ilishini o'tkazadi.

### Relizga tayyorgarlik cheklisti (Release Checklist):
```
[ ] 1. 0 ta Blocker va 0 ta Critical darajadagi ochiq buglar.
[ ] 2. Barcha avtomatlashtirilgan regressiya testlari 100% yashil o'tgan.
[ ] 3. Asosiy biznes oqimlari (Smoke Testing) qo'lda muvaffaqiyatli tekshirilgan.
[ ] 4. Qaytarish rejasi (Rollback Plan) tayyor (agar nimadir buzilsa, eski versiyaga qaytish).
[ ] 5. Ma'lum bo'lgan mayda nuqsonlar (Known Issues) hujjatlashtirilgan.
```

* **GO:** Barcha shartlar bajarilgan, reliz muvaffaqiyatli amalga oshiriladi.
* **NO-GO:** Kritik xavflar mavjud, reliz bekor qilinadi yoki kechiktiriladi.

---

## 3. Favqulodda Hotfix jarayoni

Agar relizdan so'ng jonli muhitda (Production) to'satdan jiddiy xato aniqlansa:

```
[Production: Bug topildi]
          │
          ▼
[1. 'main' tarmog'idan 'hotfix/...' branch ochish]
          │
          ▼
[2. Dasturchi minimal o'zgarish bilan tuzatadi]
          │
          ▼
[3. QA: Aynan shu xato va qo'shni 2-3 ta asosiy oqimni tezkor sinaydi]
          │
          ▼
[4. Shoshilinch deploy (Hotfix)]
          │
          ▼
[5. Xato kelib chiqish sababini tahlil qilish (Post-Mortem)]
```

<Callout type="info">
  **Qoida:** Hotfix paytida hech qachon boshqa yangi funksiyalarni aralashtirib yubormaslik kerak! Faqat va faqat o'sha xatoni tuzatuvchi minimal kod qatorlari yuborilishi shart.
</Callout>
