# Agile va CI/CD Muhitida QA Roli

Agile metodologiyasida sifat — bu faqat QA ning emas, butun jamoaning umumiy mas'uliyatidir. QA bu yerda "darvozabon" (gatekeeper) emas, balki sifat madaniyatini oshiruvchi yo'lboshchidir.

---

## 1. Scrum marosimlarida QA ning o'rni

| Marosim | QA nima qiladi? | Nega bu muhim? |
| :--- | :--- | :--- |
| **Grooming / Refinement** | Talablarni o'qiydi, "Agar foydalanuvchi internetni o'chirib qo'ysa nima bo'ladi?" kabi savollarni beradi. | Kod yozilishidan oldin talablardagi xatolarni 0-daqiqada ushlab qoladi (**Shift-Left**). |
| **Sprint Planning** | Vazifalarni baholashda (Story Points) faqat dasturlash vaqtini emas, balki sinash va regressiya vaqtini ham hisobga oldiradi. | Sprint oxirida "QA ulgurmadi" degan bosim paydo bo'lishining oldini oladi. |
| **Daily Standup** | Nimalar sinovdan o'tgani, qaysi vazifalarda to'siqlar (Blockers) borligini aytadi. | Jamoaga sifat bo'yicha real holatni yetkazadi. |
| **Retrospective** | O'tgan sprintdagi jarayon kamchiliklarini (masalan, "Dasturchilar test muhitini kech berishdi") ochiq muhokama qiladi. | Keyingi sprintlarda xatolarni takrorlamaslikni ta'minlaydi. |

---

## 2. DoR (Definition of Ready) va DoD (Definition of Done)

Ko'p jamoalarda tartibsizlik aynan ushbu ikki tushunchaning yo'qligi sababli kelib chiqadi:

```
┌─────────────────────────┐         ┌─────────────────────────┐
│ DoR (Boshlashga tayyor) │ ──────► │ DoD (Yakunlandi)        │
├─────────────────────────┤         ├─────────────────────────┤
│ ✓ Talablar aniq yozilgan│         │ ✓ Kod dasturchi ko'rgan │
│ ✓ Figma dizayn tayyor   │         │ ✓ Unit testlar o'tgan   │
│ ✓ Qabul mezonlari (AC)  │         │ ✓ QA sinovidan o'tgan   │
│   aniq ko'rsatilgan     │         │ ✓ Buglar qolmagan       │
└─────────────────────────┘         └─────────────────────────┘
```

* **DoR (Definition of Ready):** Vazifani dasturchi ishga olishidan oldin bajarilishi kerak bo'lgan shartlar. Agar dizayn to'liq bo'lmasa yoki qabul mezonlari (Acceptance Criteria) yo'q bo'lsa, vazifa sprintga olinmaydi!
* **DoD (Definition of Done):** Vazifa "Bajarildi" (Done) ustuniga o'tishi uchun qat'iy mezonlar. Agar QA testlamagan bo'lsa, vazifa hech qachon Done bo'lmaydi.

---

## 3. QA ning CI/CD Quvurlaridagi (Pipeline) o'rni

**CI/CD (Continuous Integration / Continuous Delivery)** — dasturchi yozgan yangi kodni avtomatik ravishda tekshirib, sinovdan o'tkazib, serverga joylash jarayoni.

```
[Git Commit]
     │
     ▼
[1. Lint & Static Analysis]  ──► Kod formati to'g'rimi?
     │
     ▼
[2. Unit Tests]              ──► Dasturchilarning funksional testlari (Jest/JUnit)
     │
     ▼
[3. Build & Deploy Staging]  ──► Test muhitiga joylash
     │
     ▼
[4. QA Automated Tests]      ──► Playwright E2E va Postman API testlari (Smoke)
     │
     ▼
[5. Production Deploy]       ──► Jonli muhitga xavfsiz chiqarish
```
