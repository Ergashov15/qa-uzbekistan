# Production Sinovi va Observability (Kuzatuvchanlik)

Ilgari QA muhandisining ishi dastur production serveriga chiqishi bilan tugagan deb hisoblanar edi. Bugungi kunda ilg'or kompaniyalar (Uber, Netflix, Spotify) dasturni jonli muhitda nazorat qilib sinash amaliyotidan foydalanadilar.

---

## 1. Feature Flags (Xususiyat kalitlari) orqali xavfsiz reliz

**Feature Flag** — bu dasturdagi muayyan yangi funksiyani kodni qayta deploy qilmasdan, boshqaruv paneli orqali yoqish yoki o'chirish imkonini beruvchi kalitdir.

```
if (featureFlags.isEnabled('NEW_CHECKOUT_FLOW', user.id)) {
  showNewCheckout(); // Yangi to'lov sahifasi
} else {
  showOldCheckout(); // Eski ishonchli to'lov sahifasi
}
```

### QA uchun afzalliklari:
1. **Jonli sinov:** Yangi funksiyani butun dunyodan yashirib, faqat QA va ichki xodimlar akkaunti uchun yoqib, haqiqiy ishlab chiqarish ma'lumotlarida sinash mumkin.
2. **Kutilmagan xatoda bir zumda o'chirish (Kill Switch):** Agar yangi sahifada xatolik chiqsa, serverni qayta yig'masdan (Rollback qilmasdan), 1 soniya ichida kalitni o'chirib qo'yish kifoya.

---

## 2. Canary Release va Blue-Green Deployment

Yangi versiyani bir vaqtda 100% foydalanuvchiga berish o'rniga, uning xatarlarini bosqichma-bosqich boshqarish:

```
[Barcha Foydalanuvchilar]
          │
          ├──────► 95% Trafik ──► [Eski Barqaror Versiya: v1.0]
          │
          └──────►  5% Trafik ──► [Yangi Sinov Versiyasi: v2.0 (Canary)]
                                          │
                                          ▼
                         [Xatolar soni tekshiriladi: Sentry/Grafana]
                         - Agar xato bo'lmasa ──► 20% ──► 50% ──► 100%
                         - Agar xato bo'lsa   ──► Zudlik bilan bekor qilinadi
```

---

## 3. Observability (Kuzatuvchanlik) — QA ning yangi quroli

Tizimda xato bo'lganda dasturchiga *"Menda nimadir ishlamay qoldi"* deyish yetarli emas. Professional QA xatolik izini server loglaridan topib bera olishi kerak.

### Uchta asosiy ustun:
1. **Logs (Loglar):** Tizimda sodir bo'lgan aniq voqealar matni (masalan: *"Foydalanuvchi 45 so'rov yubordi, lekin baza javob bermadi"*).
2. **Metrics (Metrikalar):** Raqamli ko'rsatkichlar — CPU yuklanishi, server xotirasi, soniyasiga tushayotgan 500-xatoliklar foizi (Grafana, Prometheus).
3. **Distributed Tracing (Taraslar):** Bitta so'rov 10 ta mikroxizmat (Microservices) orqali o'tganda uning har bir nuqtada qancha vaqt yo'qotganini ko'rsatuvchi xarita.

### Request ID (`X-Request-Id`) bilan ishlash:
Brauzer konsolida yoki tarmoq so'rovida `X-Request-Id: a8f4-90cd...` ko'rsatiladi. QA ushbu unikal ID ni **Sentry** yoki **Kibana / Datadog** qidiruviga qo'yib, serverda aynan o'sha soniyada qaysi qatorda qanday istisno (Exception) chiqqanini bir zumda aniqlay oladi.

<Callout type="info">
  **Xulosa:** Observability ni biladigan QA muhandisi xatolik sababini topish vaqtini (Mean Time to Detect - MTTD) bir necha soatdan 2-3 daqiqagacha qisqartiradi.
</Callout>
