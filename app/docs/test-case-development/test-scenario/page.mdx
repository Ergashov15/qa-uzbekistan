# Test Scenario: Sinov Ssenariysi

**Test Scenario** — bu dasturiy ta'minotning qaysi funksiyasi, imkoniyati yoki foydalanuvchi xatti-harakati sinovdan o'tkazilishi kerakligini belgilovchi bir qatorli, yuqori darajadagi ta'rifdir.

Oddiy so'z bilan aytganda: **Test Scenario — bu "NIMA tekshirilishi kerak?" (What to test) degan savolga javob beradi.**

---

## Nega Test Ssenariylari Tuziladi?

1. **To'liq qamrovni kafolatlash:** Talablardagi birorta ham muhim funksionallik nazardan chetda qolmasligini ta'minlaydi.
2. **Vaqtni tejash:** Loyihada vaqt o'ta tig'iz bo'lganda (masalan, favqulodda tezkor relizlarda) batafsil test-keyslar yozish o'rniga, ssenariylar asosida tezkor sinov o'tkazish mumkin.
3. **Mijoz va menejerlar uchun qulaylik:** Biznes vakillari minglab batafsil qadamlarni o'qib o'tirmay, qaysi ssenariylar sinovdan o'tganini osongina ko'ra oladilar.

---

## Test Scenario va Test Case O'rtasidagi Farq

| Mezon | Test Scenario | Test Case |
| :--- | :--- | :--- |
| **Asosiy savol** | Nima sinovdan o'tkaziladi? (*What to test*) | Qanday qilib qadamma-qadam sinash kerak? (*How to test*) |
| **Tafsilot darajasi** | Yuqori darajadagi umumiy tushuncha | O'ta batafsil: qadamlar, ma'lumotlar, kutilgan natija |
| **Hajmi** | Odatda bitta jumla | Bir nechta ustun va qatorlardan iborat jadval |
| **Munosabat** | Bitta Test Scenario ichida bir nechta Test Case lar bo'lishi mumkin (1 dan ko'p) | Bir dona aniq holatni ifodalaydi |

## Amaliy Misol: Elektron Tijorat Tizimi

- **Talab:** Buyurtmalar bo'limi.
- **Test Scenario 01:** Foydalanuvchining to'lov kartasi orqali buyurtma berish jarayonini tekshirish.
  - *Tegishli Test Case 1:* Balansida yetarli pul bor karta bilan muvaffaqiyatli to'lov (Ijobiy sinov).
  - *Tegishli Test Case 2:* Mablag'i yetarli bo'lmagan karta bilan to'lov qilish (Salbiy sinov).
  - *Tegishli Test Case 3:* Muddati o'tgan karta ma'lumotlarini kiritish (Salbiy sinov).
  - *Tegishli Test Case 4:* To'lov paytida internet uzilib qolishi (Chegaraviy sinov).
